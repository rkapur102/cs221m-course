Last week, we looked closely at the inputs behind every interchange intervention. An IIA score is computed over a set of base and source pairs, so it can only be as informative as those pairs. Lecture 9 treated counterfactual design (i.e. the choice of these pairs) as part of the method. A useful pair meets three criteria: 1) it changes the target variable, 2) that change alters the output the algorithm predicts, and 3) patching a competing variable predicts a different output (this is actually what you should check first!). In the multiple-choice task from the notebook, our causal model tracked both which position held the correct answer and which letter labeled it. In an ordinary pair, these two move together. In the notebook’s example, the base question “The ball is red. What color is the ball?” lists A. red and B. blue, so the answer is A. A source that swaps the two options moves the correct answer to the second position and changes its letter to B. Patching the position tells the model to answer with whatever letter is in the second position (B), and patching the letter tells it to answer B directly; both patches predict the same output, and even a perfect IIA score cannot distinguish which variable a site encodes. We therefore built isolated datasets whose pairs move the correct answer while keeping its letter (here, a source about a blue ball that lists B. red and A. blue) so that the two patches predict different answers: B and A. This is the same idea as our week 2 minimal pairs, where changing exactly one aspect of the input let us attribute any change in the output to that aspect alone, now applied to activations.

In Lecture 10, we dropped the assumption that each variable is aligned with a disjoint set of neurons. Since neurons are often polysemantic (each responds to several unrelated concepts), a variable may be encoded in a direction distributed across many of them. Abstraction under translation first recarves the network’s activations with an invertible map (a translation, which loses no information) and then aligns variables, and distributed alignment search (DAS) learns that map as a rotation. In the notebook, on the MLP trained for hierarchical equality, the first half of the rotated dimensions carried E₁ and the second half carried E₂ (the algorithm’s two intermediate variables: whether the first pair of letters is equal, and whether the second pair is), with an IIA of 0.999. The RAVEL benchmark (factual prompts that query different attributes of the same entity, such as the country or continent of a city) then asked something stricter of language models: changing the continent of Paris to Asia should leave its country as France. Patching the entire residual stream vector failed this Isolate test (an intervention on one attribute must leave the others unchanged), while DAS and multi-task DAS (MDAS), which trains a single rotation to change the target attribute and preserve all the others at once, can separate attributes even when they are encoded in overlapping sets of neurons.

We've now completed all of the main content! Stepping back, we opened the course with three levels of explanation: a model’s behavior, the algorithm it might follow, and the place inside the model where that algorithm runs. The weeks since have moved through those levels in order. Behavioral tests showed that a benchmark score can mask shortcuts and memorization. Probes then let us decode information from activations, and interventions helped us ask whether the model actually uses that information. Mediation analysis traced where information flows through the model, and causal abstraction gave us a precise standard for when an algorithm faithfully describes what the network computes. Counterfactual design then ensured that our input pairs can reveal which of two candidate variables a site actually encodes, and DAS let us find variables encoded in directions distributed across many neurons. Across all of this, there is one concise throughline to remember: an explanation of a model is a claim about counterfactuals, and we can trust an explanation when an intervention changes the output exactly as predicted!

What we learned from last week’s notebooks

Designing counterfactuals

  • Causal variables and structure: describing a task in terms of causal variables and the relationships between them.
  • Counterfactual datasets: the three dataset roles (targeted, isolated, and random) and what each is evidence for.
  • Checking at the causal-model level: confirming that a dataset can tell competing variables apart before running neural interventions.

Abstraction under translation

  • Translation: recarving a model’s variables with an invertible map that preserves its causal structure.
  • Distributed alignment search: learning a rotation of activation space whose subspaces align with high-level variables.

Localizing and disentangling concepts

  • Cause and Isolate: an intervention on one attribute should change it while leaving every other attribute intact.
  • From neurons to directions: how full-vector patching, DBM, DAS, and MDAS differ in how precisely they localize an attribute.
